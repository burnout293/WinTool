L'écran d'analyse, et la norme qui le compose

WinTool examine le PC, montre ce qu'il a trouvé, on coche, et seulement ensuite il agit. Ce que l'écran affiche, ce sont les scripts qui le décrivent, ligne par ligne : une barre de progression, des éléments trouvés, des cases, des mesures, des notes. Rien de ce qui suit n'est dessiné à la main : chaque écran est fabriqué à partir des lignes que le script écrirait.

Mon conseil : C, la barre d'espace, pour le mode Simple ; B pour l'Expert

En mode Simple, la question est « qu'est-ce qui prend de la place, et qu'est-ce que je libère ? ». La barre répond d'un coup d'œil : 10 Mo de fichiers temporaires à côté d'1,1 Go de cache de Windows Update, ça se voit avant de se lire. Le détail reste dessous pour qui veut décocher un reste de programme mal reconnu.

En mode Expert, une action à la fois, avec tout le détail : B.

Quatorze actions, toutes les briques

Chaque exemple montre à gauche l'écran, à droite ce que le script déclare (dans son entête) et ce qu'il écrit pendant l'analyse. Modifiez ces lignes : l'écran suit. Essayez de passer une taille à 0, d'ajouter checked=false, ou une ligne [ITEM] de plus.

« Vu en Simple » montre ce qu'un débutant verrait en dépliant le poste : les lignes marquées show=expert disparaissent, celles marquées show=simple apparaissent. Le script n'a rien écrit deux fois.

Le résumé : le script regroupe, on déplie au besoin

Chaque action se résume en un ou deux postes. C'est le script qui les compose, en rangeant ses cases dans des groupes ([group:Junk]) : six lignes de nettoyage deviennent « Fichiers inutiles » et « Anciennes mises à jour de Windows ». Le chevron déplie un poste en arborescence : on y retrouve chaque élément, et on y décoche le reste de programme mal reconnu.

Ce qui ne parle qu'à l'Expert, le script le dit, ligne par ligne (show=expert : une clé de registre, des journaux d'erreurs, des cookies) ou pour toute l'action (## show : expert : les doublons, les gros fichiers). Un élément caché reste compté et suit la case qui le contient ; le détail annonce qu'il existe.

La case d'un poste ne coche que ce que le script recommande. Un élément « À vérifier » se coche à la main, une fois le poste déplié — le poste affiche alors ce qu'il reste de côté.

Six graphiques, l'anneau par défaut

L'anneau dit le mieux d'où vient la place. Les cinq autres restent au choix dans les réglages : la barre d'espace, le fond des lignes, les rectangles, la gaufre, la jauge seule. Tous partagent la même liste, avec ses chevrons — sauf les rectangles, qui sont eux-mêmes la liste.

Une vue par action, choisie par le script — la même dans les deux modes

WinTool dispose les actions (onglet 1) ; chaque script dit comment sa partie s'affiche, d'un mot : ## view : donut. Cette vue sert en Simple comme en Expert : le script écrit ses lignes une fois, et ce qui change d'un mode à l'autre se règle ligne par ligne (show=expert). Pour le cas rare d'une vue qui ne convient qu'à un mode : ## view : gauge expert=table. Une liste peut aussi choisir la sienne : [items] [view:table]. Sans rien déclarer, c'est la liste à cocher.

« Voir le code », sur chaque vue : l'entête (la ligne surlignée est la seule propre à la vue), l'analyse en PowerShell, les lignes qu'elle écrit, puis l'action — avec ce que WinTool lui renvoie, recalculé à chaque case cochée. Les quatorze vues sont branchées sur les mêmes cases : cocher ici coche dans les autres onglets.

Les vues sont un catalogue fermé, dessiné par WinTool : un script en choisit une, il n'en dessine pas. C'est ce qui garde l'application cohérente, accessible et traduite.

B, avec des panneaux

À droite, des panneaux qu'on ouvre et ferme (les pastilles en haut) : Réglages appliqués (le rappel des variables), Progression (le journal, filtrable : étapes, constats, et les canaux que le script ouvre lui-même avec [LOG] Registry …), Ce qui sera fait (la liste exacte, d'après les cases), Ce que reçoit le script (le WINTOOL_CONFIG réel), Points d'attention, Historique, Provenance, Espace disque. Le script propose ceux qui s'ouvrent d'office (## panels : plan progress) ; l'utilisateur ajoute ou retire.

Essayez : « Retirer les restes » (journal avec un canal « Registry »), puis décochez un reste et regardez « Ce qui sera fait » et « Ce que reçoit le script » suivre.
